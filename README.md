# Credit Risk Score Using Binary Classification

## Project Overview

This research project explores whether information about a loan applicant can help classify their recorded credit risk as **good** or **poor/bad**. It uses the German credit dataset and plans to compare multiple binary classification models.

The project is intended for people studying or reviewing loan risk. It is a research and learning project, not a validated system for making real loan decisions.

## Research Aim

The project aims to:

- Explore how applicant features relate to the recorded credit-risk class.
- Prepare the data for binary classification.
- Compare multiple classifiers using the same evaluation approach.
- Examine model errors and explain the project’s limitations.

The project predicts a class from the dataset. It does not yet create or validate a real-world credit score.

## Dataset

The project uses the [German Credit dataset from Kaggle](https://www.kaggle.com/datasets/benjaminmcgregor/german-credit-data-set-with-credit-risk/data).

The raw file is stored at:

`data/raw/german-credit-data-set-with-credit-risk.csv`

It contains applicant information such as age, sex, job, housing, savings, checking-account status, credit amount, loan duration, and loan purpose. The `Credit Risk` column is the target.

### Target Label Mapping

The original labels are converted for binary classification:

| Original value | Meaning | Project label |
| --- | --- | ---: |
| `1` | Good credit risk | `0` |
| `2` | Poor/bad credit risk | `1` |

The original raw dataset should remain unchanged. The mapped data is saved separately as an intermediate dataset.

## Current Exploratory Findings

The saved notebook outputs currently report **954 rows and 11 columns**. These results should be confirmed by rerunning the notebooks before final reporting.

The saved results show:

- Good-risk class (`0`): 665 records, about 69.7%.
- Poor/bad-risk class (`1`): 289 records, about 30.3%.
- Missing values: 175 in `Saving accounts` and 378 in `Checking account`.
- Credit-risk proportions vary across some categories, including sex, housing, savings, checking-account status, and loan purpose.
- The mean credit amount is higher for class `1` than class `0` in the current saved output.

These are preliminary patterns in this dataset. They do not show that a feature causes a credit-risk outcome. Small category groups and missing data may make some comparisons uncertain.

## Project Workflow

1. **Data quality:** inspect the dataset’s shape, columns, data types, missing values, duplicates, and target labels.
2. **Exploration:** review class balance, feature distributions, and relationships between features and credit risk.
3. **Preprocessing:** decide how to handle missing values, categories, and numeric features.
4. **Model comparison:** compare multiple binary classifiers, such as Logistic Regression, Decision Tree, Random Forest, and XGBoost.
5. **Evaluation and error analysis:** compare model results and review mistakes with measures such as precision, recall, F1, and a confusion matrix.

No best model or final performance result has been selected yet.

## Limitations and Responsible Use

- Results describe the supplied dataset and may not apply to other applicants, lenders, or time periods.
- The dataset may contain missing values, class imbalance, or other limitations that affect model results.
- Observed relationships are not proof of cause and effect.
- A model prediction should not be the sole basis for approving or rejecting a real loan.
